# 무인 세차장 관리자 앱과 FreeLang fx2 검증 기록

작성일: 2026-08-19

## 문제

무인 세차장 사업자가 여러 매장을 하나의 관리자 앱에서 운영하고, 고객 이탈을 줄이기 위해 이벤트·RF 선불카드·고객 반응을 지속적으로 관리할 수 있는 구조가 필요했다. 동시에 73 서버에서 운영 중인 기존 PM2를 건드리지 않고 FreeLang fx2의 실행 가능성도 확인해야 했다.

## 세차장 앱에서 정리된 범위

- 여러 매장과 매장별 고객·이벤트·포인트 관리
- 소유자·직원 권한 분리
- RF 선불카드 충전·사용·소진 원장
- 분실 카드 중지와 거래 기록 보존
- 이벤트 기간·지급 시기·혜택을 관리자 설정
- 공개 좋아요·댓글과 관리자 숨김·삭제
- 고객 대시보드와 관리자 결과·참여율 확인

MVP에는 매장·고객·카드·거래·이벤트·댓글·좋아요 데이터 흐름과 관리자 화면이 반영됐다. GitHub 저장소의 마지막 확인 커밋은 `3bcd96f`다.

## FreeLang 검증

73 서버의 기존 v11 `test-builtins.fl`에서는 `run-ast` 자체 인터프리터의 타입 오류가 재현됐다.

```text
[E_TYPE_MISMATCH] +: 인자 1번에 string 전달됨 — number 필요
```

반면 최소 함수 테스트는 정상 동작했다.

```lisp
(defn bump [i] (+ i 1))
(println (bump 0))
```

따라서 기본 숫자 연산보다 테스트 파일 내부의 자체 인터프리터 스코프 처리 문제로 범위를 좁혔다.

fx2는 기존 PM2와 분리해 검증했다.

- 레지스트리 `/health` 응답 성공
- `/fx/packages` 패키지 목록 조회 성공
- `/fx/fns/str-count` 함수 정보 조회 성공
- 잘못된 경로의 `404` 응답 확인
- 캐시 제거 후 네트워크 포함 네이티브 빌드 성공
- 새 바이너리의 HTTP 헬스 응답 성공

## 빌드 오류와 해결

처음에는 OpenSSL·libcurl 심볼 링크 오류가 발생했다. 라이브러리 부족이 아니라 이전 모드의 `runtime/libfx.a` 캐시가 재사용된 것이 원인이었다.

임시 복사본에서 다음 캐시를 제거하고 다시 빌드했다.

```bash
rm -f runtime/libfx.a runtime/.libfx_hash
```

이후 `--no-net` 빌드와 네트워크 포함 일반 빌드 모두 성공했다. `--no-net`은 stub 모드라 HTTP 응답을 제공하지 않으며, 실제 서버 검증에는 일반 빌드를 사용해야 한다.

## 운영 안전성

73 서버의 기존 PM2에는 `stop`, `restart`, `delete`, `reload`를 실행하지 않았다. fx2 원본 저장소도 기존 사용자 수정이 있어 직접 덮어쓰지 않고 `/tmp` 임시 복사본으로 테스트했다. 모든 테스트 프로세스와 테스트 포트는 종료·정리했다.

## 남은 작업

- `test-builtins.fl` 자체 인터프리터의 `run-ast`·스코프 타입 보존 수정
- fx2 패키지 설치·삭제·테스트 API 검증
- 세차장 앱 DB·인증·실제 RF 연동
- 이벤트 알림과 운영 통합 테스트
- PM2 운영 적용 여부 최종 승인

이번 글은 실제 실행 결과를 기준으로 작성했으며, 아직 완료되지 않은 기능은 완료된 것으로 표시하지 않았다.
